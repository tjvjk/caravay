# Как распространялся systemAudioDump

Проверено 8 сентября 2026 года. Вопрос: какие публичные свидетельства продвижения `sohzm/systemAudioDump` можно использовать как ориентир для `caravay-capture`?

## Подтверждённые точки видимости

- **Ссылка из приложения с большей аудиторией.** README `sohzm/cheating-daddy` в разделе Audio Capture прямо указывает SystemAudioDump как средство захвата системного звука на macOS. На просмотренной странице у приложения около 5,6 тыс. звёзд. Ссылка ведёт через старый адрес `Mohammed-Yasin-Mulla/Sound`, который сейчас перенаправляет на `sohzm/systemAudioDump`. Это подтверждает заявленную интеграцию и возможность перехода из большого проекта, но не число переходов. [README cheating-daddy](https://github.com/sohzm/cheating-daddy#audio-capture), [старый адрес](https://github.com/Mohammed-Yasin-Mulla/Sound).
- **Витрина автора на GitHub.** SystemAudioDump входит в закреплённые репозитории профиля `sohzm`, рядом с cheating-daddy. На просмотренной странице профиля около 870 подписчиков. Это установленная точка видимости, а не доказательство происхождения звёзд. [Профиль](https://github.com/sohzm).
- **Личный сайт.** Страница автора об open source перечисляет SystemAudioDump среди личных проектов, со ссылкой на репозиторий и отметкой о спонсорстве Recall.ai. Числа звёзд на сайте отличаются от GitHub, поэтому не используются как актуальная статистика. [Страница open source](https://soham.sh/opensource/).
- **Спонсорство.** В начале README SystemAudioDump размещено объявление о спонсорстве Recall.ai. Ссылка на продукт спонсора содержит `utm_campaign=sohzm-system-audio-dump`, `utm_medium=sponsorship` и `utm_source=github`. Это подтверждает рекламное размещение в пользу Recall.ai внутри репозитория. Обратное продвижение утилиты со стороны Recall.ai и влияние спонсорства на рост аудитории не установлены. [README SystemAudioDump](https://github.com/sohzm/systemAudioDump), [ссылка спонсора](https://www.recall.ai/product/desktop-recording-sdk?utm_campaign=sohzm-system-audio-dump&utm_medium=sponsorship&utm_source=github).

## Что остаётся неизвестным

Основной исследователь нашёл публичное продвижение **cheating-daddy через спор о лицензии**: [пост на Reddit](https://www.reddit.com/r/opensource/comments/1lr7g2m/my_open_source_project_was_stolen_and_relicensed/), где аккаунт `sohxm7` в комментарии называет cheating-daddy своим проектом, ведёт на [публикацию в X](https://twitter.com/soham_btw/status/1940952786491027886). На [Hacker News](https://news.ycombinator.com/item?id=44460552) автор `sohzm` опубликовал материал 4 июля 2025 года в 02:04 UTC; на момент проверки [API HN Algolia](https://hn.algolia.com/api/v1/items/44460552) показывал 947 баллов. Это свидетельство внимания к приложению, которое ссылается на capture, но не доказательство конверсии в аудиторию capture.

По поиску основного исследователя по точному имени отдельный анонс SystemAudioDump на Reddit, X или Hacker News пока не найден; запросы HN Algolia по имени и URL дали `nbHits=0`. Это не доказательство отсутствия анонса: возможны другие названия, удалённые публикации и неполная индексация. Поиск под старым адресом может дополнить картину.

Публичные страницы подтверждают ссылки, размещение в профиле и спонсорский блок. Без аналитики владельца они не позволяют установить основной источник трафика, долю переходов из cheating-daddy, расходы на продвижение или причинную связь между публикациями и звёздами.

## Вывод для Caravay

Рабочая гипотеза: отдельная небольшая утилита может получать видимость через приложение, которое её использует, и через публичные страницы автора. Для `caravay-capture` воспроизводимы отдельный репозиторий, заметная ссылка из README Caravay, пример реального использования и закрепление в профиле. Эти действия следуют из обнаруженных размещений; их эффективность пока не измерена.
